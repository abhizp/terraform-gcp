RAID : redundant array of inexpensive disk / redundant array of independent disk.
-- multiple disk are connected to make a single logical unit
-- provides redundancy and improved performance or both compared to a single disk
-- different raid levels give us different levels of redundancy/performance
-- can be managed by software from OS or by RAID controller in hard ware

RAID 0 : AKA stripped set
-- better performance, no redundancy
-- data is split evenly accross all the set accross disk, same data split and not copied hence no redundancy
-- if any disk in the set fails, then all the data is lost.

-- the read and write is faster because there is no copying going on, and just write and read, the write and read is done simultaneously in multiple disks
-- the more number of disks the more better performance, write and read is done parallelely in these disk hence increasing performance.

-- you can use different disk type, RPM speed and size in same storage system but not in same raid group.
-- using different capacity disks, the usable size is limited to smallest disk size.

RAID 1 : AKA Mirrored set
-- the same data is written to both disks in the set, giving high redundancy, but less performance
-- If one disk fails, the data is stored in other disk, high redundancy
-- write performance is not improved, because writing in 2 disks
-- read performance is improved, as reads can be serviced by both disks.

RAID 4 :

Data Striping: Data is split across multiple disks (like RAID 0).
Dedicated Parity Disk: One disk is used exclusively to store parity information (used for recovery in case of disk failure).
Minimum Disks Required: At least 3 disks — 2 for data, 1 for parity
can tolerate upto 1 disk failure.

RAID 5 :

Same as RAID 4 but with distributed parity.
Data can be recreated from parity if any one of the disk fails.
read performance increased as multiple disk concurently service read, and write performance also increased.
can tolerate upto 1 disk failure.
There no single parity disk, instead there are parity blocks.

RAID 6 :

can tolerate upto 2 disk failure.
2 parity blocks distributed accross disks.
data can be recreated through parity if 2 disks fail.	
R/W performance increased

Hybrid RAID :

multiple raid levels nested for better performance.
RAID 10 -- multiple raid 1 mirrored sets are nested inside a RAID 0 striped set
RAID 0+1 -- multiple RAID 0 sets are nested into RAID 1 mirror
RAID 50( 5 + 0 ) -- multiple RAID 5 parity sets are nested into RAID 0 stripped set

SAN vs NAS

NAS ( network attached storage ) : provides file level access to storage resources.
-- the management of the file system resides with the remote storage system.
-- NAS typically uses the already existing data network infra

SAN ( storage area networks ) : provides block level access to storage resources.
-- the client manages the its allocated space on storage system as if it was a local hard disk
-- the file system management resides with the client.
-- gives highest control over storage devices, very low level access.
-- SAN has traditionally got a seperate dedicated storage network infra.

Boot from SAN : 
You can boot your OS from a SAN, having no hard drive at the local server, all the bootable files are stored in the SAN.
no storage is reuired at all, without local storage you can bootup, this creates diskless servers.
There can be boot from SAN, but not NAS, it not possible.

Virtualization : creating VM on a already present hardware.

host : a physical server which has RAM, memory, storage interface, network interface, plain device, nothing on top of it.
hypervisor : this is installed on the plain host, its like a agent, which manages how much storage, RAM, memory, network bandwidth is to be given to each VM on the shared infra
exsi -- is by VMware
VM : virtual machine's is being created on the hypervisor, multiple VM's can be created upon hypervisor and each VM has its own Operating system.

Types of hypervisor:

1. Baremetal hypervisor, TYPE 1 hypervisor : its created/installed on the plain hardware server, and it takes ownership of the hardware, there is no undrlying OS below this.
eg : VMware Exsi, citrix, microsoft Hyper-v.

2. TYPE 2 hypervisor : hypervisor is installed/running on your local system, its installed on an already existing OS, it works on that OS, and it creates multiple VM's on that.
eg : VMware workstation, parallel for MAC, VMware playstation.

Hypervisor is the platform on which the VM's run.

Food groups:
1. CPU -- the hypervisor allocates vCPU to each VM, each VM requires specific vCPU cores, which had to be bought, after buying its allocated from physical CPU and is converted to vCPU and allocated further.

2. Memory -- the host's physcial memory is being shared among the guest VM's, sometimes the multiple guest VM's can share same memory, not at the same time, but when free.
          -- you can also reserve the memory for your own paticular VM.
		  -- the hypervisor smartly allocates host memory accross guest VM's

3. Network -- every VM has its own vNIC's presented to it as physcial NIC
		   -- virtual switch is present on each hypervisor, in case if the internal VM's want to connect and a virtual switch is connected pNIC to connect to actual switch
		      to connect to internet.

4. Storage -- vSCSI is given to each VM, 
           -- scsi commands from VM are passed to hypervisor and then passed through storage adapters to storage area.
		   -- decoupling is used for mobility as there is no direct contact between storage and VM's its only through hypervisor, which allows to for VM migration.

fdisk command:

-- fdisk command in Linux is a powerful, menu-driven command-line utility used to view, create, delete, and modify partitions on hard drives and storage devices
-- Because modifying partition tables can destroy existing data, you must always run fdisk with root privileges using sudo

Common fdisk CLI Arguments:
sudo fdisk -l: Lists all available storage drives and their existing partition layouts.
sudo fdisk -l /dev/sdX: Displays the partition layout of one specific storage drive (e.g., /dev/sda).
sudo fdisk /dev/sdX: Opens the specified drive in interactive command mode.

parted -- same as fdisk but advanced

dumpe2fs:
The dumpe2fs command in Linux prints the superblock and blocks group information for ext2, ext3, and ext4 filesystems.
-- It is a command-line tool included in the e2fsprogs package that helps system administrators inspect filesystem layout, analyze metadata, and troubleshoot corruption

⚠️ Critical Rule Before Using:
Always unmount your partition before running dumpe2fs. If you run it on a mounted filesystem, the printed metadata can be old, out of sync, or completely inconsistent

dumpe2fs [options] device
sudo dumpe2fs /dev/sda1

Common Command Options:
-h: Displays only the superblock information and skips the overwhelming block group descriptor details. This is the most popular way to use the command.
-b: Prints only the blocks that are marked or reserved as bad in the filesystem.
-f: Forces dumpe2fs to display the data even if the filesystem has feature flags that the tool doesn't fully recognize.
-g: Displays group descriptor details in a machine-readable, colon-separated value configuration.
-o superblock=block: Forces the tool to use a specific backup superblock value when examining a heavily corrupted filesystem

e2fsck:
The Linux e2fsck command is a dedicated system utility used to check and repair ext2, ext3, and ext4 filesystems.
It serves as the target backend tool when running the general fsck command on an ext-family partition

⚠️ Critical Safety Rule:Never run e2fsck on a mounted (active) filesystem. 
Checking a live, active filesystem can cause severe, irreversible data corruption because data blocks shift during the check. Always unmount the storage drive first.

sudo e2fsck [options] /dev/sdXN

Useful Command Options:
-p (Preen): Automatically fixes safe, minor errors without asking for user permission.
-y (Yes): Force-answers "yes" to all interactive repair prompts. Use with caution.
-n (No): Opens the filesystem as read-only. It acts as a risk-free test run.
-f (Force): Forces a full structural scan even if the system flags the drive as "clean".
-c (Bad blocks): Searches the drive for hardware-level bad blocks and flags them to prevent future data loss.


To safely analyze an external or non-root block device, unmount it before starting the diagnostic check:
sudo umount /dev/sdb1
sudo e2fsck -v /dev/sdb1

tune2fs:

-- The tune2fs command in Linux allows system administrators to adjust various tunable parameters on ext2, ext3, and ext4 filesystems.
-- It is a powerful utility for fine-tuning performance, changing filesystem traits, and configuring maintenance intervals without reformatting the storage drive

Because tune2fs modifies low-level data structures, you must run it with sudo or root privileges.

sudo tune2fs [options] device

[options]: The flags used to view or change specific filesystem behaviors.
device: The target partition path (e.g., /dev/sda1), or its UUID / LABEL

1. View Filesystem Superblock Information
To see the full configuration layout of a filesystem (such as block size, mount count, and feature flags), use the -l option:

sudo tune2fs -l /dev/sda1


2. Change the Filesystem Volume Label
You can set a human-readable name (label) for your partition, making it easier to reference in /etc/fstab:

sudo tune2fs -L "BackupDrive" /dev/sda1

4. Set Maximum Mount Counts Before a Check:
You can enforce a automatic integrity scan (fsck) after a partition has been mounted a specific number of times:

sudo tune2fs -c 30 /dev/sda1

To disable checking based on the number of mounts entirely, set the count value to 0 or -1.

fsck:

The fsck (File System Consistency Check) command in Linux is a powerful system utility used to check, verify, and repair structural inconsistencies in filesystems.
-- It acts as a wrapper that automatically calls filesystem-specific checkers (like e2fsck for ext4) depending on the target drive
-- CRITICAL WARNING: Never run fsck on a mounted (currently active) filesystem. Doing so will likely cause severe, 
permanent data corruption because the filesystem metadata changes while the tool is scanning it. Always unmount the target drive first.

Option			Action Description
-n: Dry run mode; answers "no" to all prompts and only reports errors without modifying data.
-y: Auto-repair all mode; answers "yes" to all prompts and automatically fixes found issues.
-p: Safe auto-repair mode; automatically fixes minor errors that do not risk data loss.
-f: Force check; forces a full scan even if the system marks the partition as completely clean.
-C: Displays a real-time progress bar (primarily supported on ext2, ext3, and ext4).
-A: Scans all filesystems configured inside your /etc/fstab configuration file.

mdadm:

The mdadm command (Multiple Device Administration) is the standard Linux command-line utility used to create, manage, and monitor software RAID arrays.
-- It interacts directly with the Linux kernel's mdraid driver to pool multiple physical storage disks into a single logical volume for redundancy, speed, or both

The mdadm manual page defines several major operation modes using specific flags:
--create (-C): Build a brand new array with dedicated superblocks on each drive.
--assemble (-A): Re-link existing parts of a previously made array into an active storage volume.
--manage: Add new spare drives or mark active drives as failed.
--grow (-G): Change the physical size, layout, or RAID level of an active array.
--stop: Deactivate an array and free up all associated system resources. 

View all active arrays and live rebuilding progress:
cat /proc/mdstat

Create a RAID 1 (Mirroring): 
sudo mdadm --create /dev/md0 --level=1 --raid-devices=2 /dev/sdb /dev/sdc

Simulate/Mark a drive as failed: Tell the system a drive is broken:
sudo mdadm /dev/md0 --fail /dev/sdb

To wipe a RAID volume entirely, follow these structural steps sequentially:
sudo umount /mnt/raidlocation                 # 1. Unmount the filesystem
sudo mdadm --stop /dev/md0                   # 2. Stop the array
sudo mdadm --zero-superblock /dev/sdb /dev/sdc # 3. Erase the RAID metadata blocks
